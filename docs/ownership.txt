# Ownership (copy of blueprint §19 and §22)

Each member owns a vertical slice: backend packages, the React pages for those features, the tests,
the report sections and the video segment. Only edit your own packages and folders.

| | Member 1 | Member 2 | Member 3 | Member 4 |

| Backend packages | `shared` (contracts), `incident`, `priority`, `audit` | `triage`, `assignment` | `catalog`, `topology`, `sla`, `escalation` | `config`, `identity`, `notification`, `reporting` |
| Frontend folders | `features/incident`, `features/audit` | `features/triage`, `features/assignment`, `features/settings` | `features/topology`, `features/sla`, `features/catalog` | `app/` shell, `api/`, `features/auth`, `features/users`, `features/notifications`, `features/search`, `features/reports`, `features/dashboard` |

## Shared files (owned by Member 4, ask before changing)

`backend/pom.xml`, `backend/src/main/resources/application.yml`, `config/SecurityConfig.java`,
`frontend/src/App.tsx`, `frontend/package.json`, `docker-compose.yml`, `.github/workflows/ci.yml`.

## Contract changes

Anything in `shared/` needs agreement from all four in the group chat first.

## Seed order

`DataSeeder` beans run in order: catalog (M3, 10) → users (M4, 20) → historical incidents (M2, 30) →
live demo incidents (M1, 40). Only in the `dev` and `demo` profiles.

## Branches and PRs

Branch names like `m2/duplicate-detection`; small PRs; one approval from your review buddy;
squash-merge; `main` must stay green in CI. Push at least every 2 hours.
